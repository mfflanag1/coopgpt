M100 OFFLINE DESCRIPTIVE GATE: PORTABLE REPRODUCTION
17 October 2026. This reproduces observations in three public released-data
members. It does not test physical pooling, causal energy savings, reliability,
ownership, or an operational reserve contract.

ONE COMMAND

Use Python3.10+ with DuckDB1.4.1 already installed in that interpreter. This
runner does not install packages or download data. From any working directory:

  /path/to/python -I /path/to/reproduce_m100_gate.py \
    --raw-dir /path/to/local-parquet-members \
    --output /path/to/new-report.json

The script alone and the three raw members are sufficient. It has no sibling
Python dependency or hard-coded campaign directory. To additionally compare
against the preserved, unmodified inspection/supplement reports:

  /path/to/python -I /path/to/reproduce_m100_gate.py \
    --raw-dir /path/to/local-parquet-members \
    --output /path/to/new-report.json \
    --reference-dir /path/to/checks

The optional directory must contain M100_PANEL_INSPECTION.json and
M100_PANEL_SUPPLEMENT.json. Their hashes are included in the output. They are
comparison targets only: no derived result is imported into the computations.
Without them, embedded accepted key claims still provide a compact regression
comparison. Counts and timestamps must match exactly; floating summaries use
absolute tolerance1e-9 and relative tolerance1e-12.

The output parent must already exist. Existing output files and any output
inside the raw directory are refused. Choose a new name for each rerun.
Exit0 means the analysis completed and all selected comparisons passed.
Exit1 produces an ERROR or DISCREPANCY report, with details; invalid CLI paths
can fail before analysis. A missing/wrong raw hash fails before any DB is opened.

WHAT IS RECOMPUTED

For every metric: exact rows and node count; schema; timestamp range; null,
negative, zero, unmapped/noncanonical node counts; value ranges/quantiles;
exact duplicate, conflicting, all-null and mixed-null key statistics.

Internal join/grouping keys are exact epoch nanoseconds. There is no rounding
to20s or even milliseconds. Millisecond summaries are merely display fields;
submillisecond and subsecond rows are separately checked and are absent in
the pinned files. Times are UTC. Node IDs are canonical strings0 through979.

Exact repeated keys collapse before joins. A conflicting key, all-null key,
negative value, null node or null time is excluded from the clean table.
A key with nulls plus one agreed nonnull value is retained and separately
counted. No imputation, upper cutoff, health-state or workload filter is used.
The actual pinned files have no duplicate/conflicting/null/negative keys.

PSU pairs require ps0 and ps1 for the same node at the identical timestamp.
Triples additionally require total_power at that exact node/time. Delta is
total_power minus (ps0_input_power plus ps1_input_power). No assumption that
these quantities describe an identical physical meter boundary is imposed.

The runner computes timestamp node-count histograms for each raw metric,
the PSU pair panel and the triple panel, then their intersections across all
980 nodes. It also reproduces the preselected node0/node1 intersection.
The longest20s run counts consecutive timestamp observations; elapsed span
is20*(cells-1) seconds, not20*cells. Runs are postselected summaries.

Global maximum gaps use distinct timestamps with at least one clean reported
node, separately for each raw metric. They are not the maximum per-node gap,
nor an estimate of hardware failure or sensor downtime. Ties select the first
gap by start time. This avoids importing hand-added supplement fields.

RESOURCE AND WRITE BOUNDARIES

Every run creates a fresh database in an automatically deleted temporary
directory, with two DuckDB threads, a1GB buffer-memory limit, and UTC timezone.
Known-extension auto-install and auto-load are disabled. Only local parquet
paths are supplied; the code has no acquisition/network routine. Temporary
database/spill storage may exceed1GB; allow a few GB of temporary disk space.
The1GB setting limits DuckDB-managed buffer memory, not total OS process RSS.
No persistent database, original report or original raw member is written.

INTERPRETATION LIMITS

The complete retrieved members contain April1-4 observations. Their lack of
later monthly records does not establish a sensor outage or monthly uptime.
No Nagios operational states, workloads, service latency, ownership rights,
deliverability or opportunity costs enter this replay. It establishes an exact
released-data panel and its limitations, not a pooling result. The difference
between total_power and PSU sum is retained, not corrected away or explained
causally. No additional empirical claim follows from passing this runner.
