Collection: separately stored N=64 warmup, then exactly 256,512,1024,1024,256,
512,512,1024,256. One completed command buffer each. Comparison after measured
submission/wait interval uses Accelerate cblas_sgemm; all N*N entries checked.
CPU self-test validates padded stride and reference against independent fixed
4x4 golden [31,-3,-4,-5,-5,24,20,16,-6,16,16,16,-7,8,12,16], then corrupts last
entry and inserts NaN/infinity to prove complete rejection. It calls no Metal API.
Both padded actual and contiguous golden data are independently hashed and checked
against root's Python-derived canonical Float32-LE SHA256:
3528d12e2f4ce4f09b261bebe1f87a9bf13961f72a9f8fb5e8b10517db08d24a
Every completed trial records independent GPU-output and CPU-reference SHA256,
computed after timing from their own buffers, row-major Float32 bitPatterns as
little-endian bytes excluding row padding. Both signed zeros normalize to positive
zero; all other bitPatterns remain unchanged. CPU self-test changes one controlled
zero entry to negative zero and verifies identical canonical hashes. A reusable
one-row UInt32 scratch requires 4*N bytes. Root's independent reviewer checks both
hashes against independently reconstructed expected output.

Input elements are exact integers, |A|<=3, |B|<=5; every product and partial sum
has absolute bound 15*N <=15360 <2^24, permitting exact Float32 comparison.
Input padding initializes to zero and all output elements/padding initialize NaN.
CPU reference uses Metal A/B plus a separate N*N Float32 C. Explicit requested
buffers plus C and the hash scratch row are capped at 64MiB; typical largest case
is 16MiB + 4KiB total. Reported
Metal buffers distinguish mathematical payload, requested padded buffer lengths,
and resource allocatedSize. Framework internals are not measured or capped.
Device allocation counters are samples, not peak usage or allocatable capacity.

No retry, size reorder, or dropped failure rows. First failure stops collection;
the failure row and previous rows remain in the JSON. gate_passed requires CPU
self-test, successful warmup, and all nine complete, exact measured cases.
Uncaught process termination (e.g. watchdog) yields no final JSON; root must
treat missing final JSON as incomplete, never infer a pass from stdout.

Output is a same-directory unique O_EXCL|O_NOFOLLOW file (0600), fsynced and
published atomically by POSIX link to the NEW_PATH. Existing destination paths
(including dangling symlinks) are refused before Metal initialization and again
by atomic link. No existing final output is replaced. No shell commands execute
from output path text. Temporary path is removed on ordinary success/failure.
