Correctness and stopping behavior
MPS descriptors use explicit Float32 row strides; neither matrix is transposed.
CPU SGEMM sees the same explicit A/B strides and creates separate contiguous C.
The checker scans all N^2 useful entries, catches nonfinite values, and uses zero
absolute error. C is initialized to NaN, exposing unwritten useful entries. The
self-test verifies row padding does not enter the comparison. Command status and
error are checked before output acceptance. Warmup and each of the nine fixed jobs
stop the sequence at the first failure; the failed row remains in the final report.
No passing subset or adaptive workload extension is accepted.

Memory and measurement boundaries
A/B/C are Metal shared-storage buffers in the same system-memory domain. The CPU
reference reuses A/B and creates a separate C array; the script does not add GPU
capacity to physical RAM. Largest unpadded payload is 16,777,216 bytes (three
1024x1024 GPU buffers and one CPU reference). Row-stride lengths and MTLBuffer
allocatedSize are separately recorded and constrained with the reference under
64 MiB. Framework workspaces, allocator overhead and process/device peaks are not
measured by this explicit-payload bound and are correctly disclaimed. Sampled
currentAllocatedSize and recommended working set are not free memory or a proven
safe concurrency limit.

Host submit-to-completion timing starts after encode and stops after wait. It
excludes input creation, encoding and CPU reference work. GPU start/end timestamps
are retained only when finite, positive and ordered. They describe a command-buffer
interval, not complete request latency, LLM throughput or scheduling performance.
The protocol correctly keeps warmup separate and treats background activity as
uncontrolled. Power/thermal diagnostics describe conditions; no energy is measured.

Output preservation and limits
Native report publication writes/fsyncs a fresh same-directory temporary and uses
an exclusive hard link; existing targets cannot be overwritten, including a race
after the initial lstat. The Python harness creates a new output directory, bounds
the native process to 120 seconds, and retains stdout/stderr/status on timeout or
launch failure. A timeout may have no complete RAW.json because native publication
occurs at the end; that closes the gate and is disclosed, rather than being counted
as success. Per-job progress is not crash-durable and is not claimed to be.
