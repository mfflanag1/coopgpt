Prospective grounded question-answering qualification — 11 October 2026 local

Purpose and boundary
Qualify one model/workload configuration before any further scheduling or energy
study. The task is answering a natural question using a supplied passage, including
abstention when unsupported. SQuAD2.0 is a public Wikipedia reading benchmark,
not private support traffic or demonstrated economic value. Its public development
examples may have appeared in pretraining. The within-study confirmation split is
not the benchmark's hidden test and does not establish unseen-knowledge accuracy.
No energy, capacity, pooling or field-level contribution follows from this gate.

Why the task changed
The earlier KEEP/DROP task has an exact deterministic filter, making it a poor
candidate for economically useful LLM work. Its failed results remain unchanged.
This is a new prospective task and model, not a rescoring or causal model comparison.
No optional KEEP diagnostic, second model, prompt search or retry is included.

Scoring
Require a complete strict JSON object with only answer:string|null. Duplicate keys,
extra keys, other types, nonfinite JSON, malformed/trailing or excessively nested
text are schema failures. A non-string API response chunk is a transport-contract
failure; retain the chunk and abort rather than score malformed API evidence.
Answerable primary score uses the original SQuAD normalized exact match against
all nonempty-normalized official annotations: lowercase, remove ASCII punctuation,
remove articles a/an/the, normalize whitespace. This tolerates those specified
surface differences; it is not byte equality or a verbatim-span guarantee.
Original annotations with empty normalization are retained as source but excluded
from answerable golds exactly as in the official evaluator. Every answerable item
must have at least one nonempty-normalized gold. No post-response annotation repair.
Unanswerable success requires literal null, mapped to empty string for official
metric comparison. Empty strings, punctuation or an article alone cannot substitute
for null. Token-overlap F1 and source-span diagnostics never replace the primary gate.
A complete correct response with done_reason=length can pass; retain that reason.
Always-null is a frozen50% balanced-label baseline, a weak floor rather than a
competitive economic alternative. Passing does not prove superiority to specialist
QA systems, efficient retrieval tools, human workflows or the strongest baseline.

Predeclared single-candidate gate
Run all12 development questions once. Require all schemas valid, >=11 exact matches,
>=5/6 within each answerability label and >=3/4 within each length band.
Only a passing completed development stage activates36 confirmation questions.
Require all schemas valid, >=33/36 exact matches, >=16/18 within each label,
>=10/12 within each length band, and >=5/6 within each of the six crossed cells.
These are finite engineering screens with a small error budget, not confidence
bounds or certification of a population reliability rate. They were fixed before
any new model output. Both per-request correctness and failures remain in any later
useful-work denominator; qualification does not make every job correct.
No fallback after either gate fails. Infrastructure failure aborts, not semantic
rejection followed by a second prompt. Unattempted confirmation remains unobserved.

JSON grammar, explicit non-thinking mode and logged P1; no extra dry inference.

Use paired monotonic-before/wall/monotonic-after clocks. Elapsed durations and

output cap must leave>=128 tokens in4096, with no truncation logs. Counts may omit

Record source freeze before collection. Freeze model, input, code and scoring; retain
