BLIND COMPONENT EVIDENCE INVENTORY — PROSPECTIVE BOUNDED SCREEN

Question: Does an independent, structured evidence inventory reject unsupported
answers and incomplete proofs while retaining justified answers on fresh claims?
This is an authored engineering screen. No population error bound, causal model
comparison, operator benefit, serving-performance, energy or pooling claim follows.
The previous binary checker failed:21/24 joint-quality primary answers,2/3 errors
caught, one error accepted, one correct answer rejected; controls11/12 invalid
rejected and8/12 valid retained. Earlier results and annotations remain immutable.

Architecture: Each claim is the literal conjunction of TWO human-authored component
statements. The same components are visible in the primary claim and inventory
request. No model performs or is credited with finding this decomposition. The
inventory call receives only packet, component sentences and output instructions;
it NEVER receives any primary answer or control proposal, gold labels/proofs, case
rationale, class balance or prior outcomes. It searches the whole packet for support
AND contradiction of each component, returning a1/a2 each with support/contradict
proof families. Each family has0-3 alternatives; each proof has1-3 unique known
excerpt IDs. Empty family means no proof found, not proof that none exists. The
model is asked to recover all minimal alternative sufficient proofs, and mistakes
or omitted alternatives remain possible. There are no free-form quoted proofs.

All24 inventories are collected FIRST. Then24 primary calls use the prior unchanged
verdict/citation instruction on the full conjunctive claim. Calls are stateless;
no inventory response is inserted into any primary prompt. All jobs are materialized
before server startup and their exact input bindings independently checked afterward.
The paired baseline is the same24 actual primary answers before filtering. This is
not a matched comparison to the prior binary-checker cohort; different claims,
prompts, structured decomposition, and sources preclude that causal interpretation.

Domain restriction: component-separable documentation claims only. Both-supported
means the conjunction is supported; any explicitly contradicted component refutes
it; otherwise insufficient. This rule is incomplete for arbitrary compound claims:
'not both A and B' may refute a conjunction while neither component alone is false.
Exclude such joint-only constraints and cross-component disjunctions prospectively
through semantic source review. The experiment does not establish a checker for
unrestricted natural-language logic, automated decomposition, or inconsistent
source packets. Both polarities populated for any component routes to REVIEW.

Deterministic decision: Strictly parse the original primary response. Invalid JSON,
duplicate keys, invalid schema, unknown inventory IDs or conflicting inventories
route to REVIEW. With a usable inventory, derive its whole verdict: any contradiction
->contradicted; allcomponents supported ->supported; otherwise insufficient. The
primary verdict must match. For supported, its citation set must contain one complete
support proof for EACH component. For contradicted, it must contain a complete
contradiction proof for at least one component. All cited IDs must belong to the
union of the inventory's proofs on that same polarity; no unrelated citations.
For insufficient, citations must be empty. No gold fields enter this decision.
An accepted answer is preserved, not rewritten. REVIEW is an unresolved referral,
not a corrected answer or successful automatic completion; review cost is unmeasured.

Alternative proofs: the inventory may list multiple sufficient proof sets. Acceptance
needs any complete alternative, not equality to one chosen proof. If the inventory
omits a genuine alternative, a correct answer may be rejected; this is counted as a
loss, never forgiven after outcomes. Whole-case gold proof families are derived from
prospectively annotated component alternatives: minimal union for allsupported,
minimal contradiction alternatives for contradicted. Frozen relevance is the union
of those whole sufficient proofs. Positive conjunctions require genuinely different
premises for the two components. Their whole proof fits the three-citation allowance.

Inputs:24 new compound claims,4 each from six NEW official source sections at the
previously pinned repository commits:Kubernetes CPU/memory resource management;
Ray asynchronous actors;PyTorch serialization;Slurm job arrays;vLLM memory conservation;
vLLM optimization. Exact sources/licenses/hashes and retrieval metadata are saved.
Eight whole claims per verdict; supported cases have two supported components;
contradicted and insufficient cases each have one supported component and one false
or unknown component respectively. Exactly3-4 excerpts perpacket,100-450 whitespace
words, complete antecedents and exact raw character slices/transforms. This is a
selected documentation task, not empirical certification of real deployments.
Prior48 propositions are excluded by author review plus exact-string bookkeeping;
string checks alone do not prove semantic freshness. Freeze all changes before
any study inference. Independent annotation sees no gold. No post-outcome relabeling.

Controls:24 prewritten, schema-valid proposals on12 of the24 claims, one valid and
one invalid percase. Select firstfour cases of each gold label in frozen hash order.
For supported/contradicted, firsttwo receive false-insufficient controls (total4:
two decisive-positive and two decisive-negative); nexttwo receive citation errors
(total4). Four insufficient cases receive two false-supported and two false-contradicted
controls. Valid controls include four of each label. Citation errors start with the
truecomponent proof; if that happens to suffice, choose the first single excerpt
that fails whole gold, otherwise empty citations. This rule precedes all outcomes.
Every control is evaluated OFFLINE by the SAME percase inventory and deterministic
rule. Thus there are24 distinct claims and48 inference calls, not72 independent
inferences. Native and controlled results share inventories and are not replications;
never pool their accuracy. Controls target semantic failure patterns, not independent
trials. Invalid 'insufficient' is newly included after the previous native failure.

Presentation checks: two deterministic reserializations for every schema-valid
native proposal and control:compact sorted-key JSON, and reordered fields/pretty
whitespace with reversed evidence-ID order. Decisions must agree. At most96 checks;
these are software invariance checks, not fresh inference, empirical robustness
replications, or evidence that model reasoning is invariant. Invalid-schema native
answers are reported and excluded only from this software-check count, never from
the24-case workflow denominator. Inventory JSON itself is not re-inferred in variants.

Runtime: one unscored warmup plus48 scored calls. 24inventory i_ID calls in
SHA256('order:'+case_id) order, then24primary p_ID calls in the SAME order. Inventories
have cap384,primary256,warmup32. Same Qwen3:32b Q4_K_M,Ollama0.20.0,context4096,P1,
temperature0,seed0,think=false,/no_think, model/binary/manifest pins and inherited
transport/clock/host controller. Dedicated localhost11562 only; original11434 must
remain idle and is never stopped. AC or explicitly permitted battery>=60%, nominal
reported thermal state before/after every scored call, clean model/server shutdown.
Budget1800seconds with300seconds reserve before offering another request,90s request
softbound,95s clienthardbound,100s owned-server watchdog. No retries, replacements,
response-dependent scheduling, prompt changes, budget extensions or subset scoring.
Observed evaluation-count margin4096-prompt_eval_count-cap>=128 and no server input
truncation diagnostic required; not an independent tokenizer/fullprompt guarantee.
Timing/load fields are execution diagnostics only, not performance/energy estimates.

Predeclared engineering gates, all required:
1.Complete valid48-call capture, exactbindings, frozen inputs, runtime gates/cleanup.
2.All24 inventories structurally valid, known-ID-bound and nonconflicting (usable).
3.Native:zero erroneous automatic answers, at least18 correct automatic answers,
and retention of at least90% of baseline-correct answers (10*kept>=9*baseline).
4.Controlled:all12 invalid proposals rejected with a usable inventory and at least
11of12 valid proposals retained. An unusable inventory is not a credited error catch.
5.Zero deterministic presentation-check discrepancies.
These are prospective engineering thresholds, not a powered test or population guarantee.

Report inventory semantic correctness separately: all48 atomic proof/status judgments,
24 whole inventories, and recovery of all frozen proof alternatives. Extra claimed
proofs must be complete and relevant; omitted genuine alternatives are disclosed.
Inventory semantic correctness is a diagnostic, not an added post-hoc gate. Gate2
is syntactic/consistency validity and does not establish logical proof correctness.
Report all24 native outcomes:baseline joint/verdict accuracy,errors caught/accepted,
correct answers referred,totalreferrals and formatreferrals. Catching a wrong answer
does not by itself establish correct diagnosis; inspect controls and inventory.
If primary has no errors,native sensitivity is unobserved. Correct automatic yield
cannot exceed baseline when filtering preserves answers. Report correct outputs per
all offered cases, not merely accuracy among retained answers. A shared wrong
inventory can systematically accept wrong answers; this study must expose, not
assume away, that possibility.

Decision: one collection then independent source/raw audit, preserve all outcomes.
Passing justifies planning a subsequent separately frozen serving study, not running
performance/energy automatically. Failure closes this attempt with exact failure
cases and no prompt-search loop on the same outcomes. No claim of field breakthrough.
