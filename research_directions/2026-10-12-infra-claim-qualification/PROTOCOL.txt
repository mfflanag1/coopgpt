Prospective AI-infrastructure documentation qualification
12 October 2026 UTC

Purpose
Qualify one local model for informational review of operational claims against
supplied documentation. The end user is an engineer deciding whether a proposed
configuration statement is documented, contradicted, or still missing evidence.
The output is a verdict with inspectable citations; no infrastructure is changed.
This is a constructed service proxy, not measured operator demand, productivity,
real deployment safety, energy saving or independent-owner pooling.

Sources and case construction
Six documentation sections from Kubernetes, PyTorch, Ray, Slurm and vLLM are
archived at immutable repository commits with source and license hashes. They
cover GPU scheduling, CUDA memory accounting, logical resources, GRES allocation,
prefix caching and sleep/wake behavior. Snapshots may be development versions;
no local installation or released-product behavior is inferred from them.
Each packet contains four contiguous excerpt blocks. Text is verbatim except
Slurm's archived HTML is stripped of tags, decoded and whitespace-collapsed by
the saved construction rule. Character offsets are Python Unicode code-point
indices in read_text() source, not byte offsets. Qualifiers are retained.

One author created 24 claims (four per source; eight per verdict) before model
access. Initial Codex and Fable reviews received packets/claims without proposed
labels/evidence. The final Fable review also saw no author gold; the second Codex
round was packet-based re-adjudication, with intended labels disclosed for five
replacements in its change message. Initial versions and reviews are retained. Before
responses, ambiguous proof requirements and an omitted option antecedent were
repaired; initially all insufficient claims requested deployment observations,
so five were changed to undocumented technical behavior to reduce that cue.
Revisions are prospective design work, not random sampling or response tuning.
Labels, evidence alternatives, source text, prompt and code are frozen before
collection. Unresolved annotation disagreement prohibits launch. Model reviews
are not independent human specialist validation.

This is one 24-case qualification cohort. There is no development/confirmation
split and no unseen-population or statistical reliability claim. Cases reuse
source packets and are dependent. Public source knowledge may be in pretraining.
Packet lengths vary naturally; no artificial padding or forced long output.
Fresh authoring does not establish contamination-free capability or novelty.
The prior 8/12 SQuAD outcome remains a closed separate study; both task and rubric
have changed, so cross-study score differences cannot identify a model improvement.

Task and scoring
RUBRIC.txt defines supported, contradicted and insufficient relative to the packet.
The exact response has verdict and evidence fields only. At most three unique
excerpt IDs; no prose. A correct supported/contradicted response must contain
one complete prospectively accepted proof and only relevant corroborating IDs.
Evidence ordering and JSON-key ordering do not matter. For insufficient, cite [].
Malformed JSON, duplicate/extra keys, wrong types, nonfinite values and deep
parser errors fail schema. Unknown/irrelevant citations or incomplete proofs fail
citation correctness. A correct verdict with bad citations is not joint success.
Primary metric is joint verdict-and-citation success on all 24 offered cases.
Secondary metrics separate schema, verdict, citation and false-support errors.
Correct complete length-ended responses may pass; terminal reason is retained.
Gold labels, proofs, rationale, source metadata and class counts never enter the
request; the model receives only the fixed public instruction, excerpts and claim.
Case IDs/order are deterministic hashes of source identity and claim, not labels.
No post-response additions to accepted evidence or labels are allowed.

Gate and stop rule
Require 24/24 schemas valid, >=22/24 joint successes, >=7/8 within supported and
contradicted, 8/8 within insufficient, and zero predictions of supported on any
contradicted/insufficient claim. Run all 24 once unless infrastructure fails.
No prompt selection, fallback model, second round, dropped failures or automatic
retry. Any unresolved data/clock/host/transport integrity fault prevents promotion.
A failed gate ends this study; an abort preserves partial and orphan captures.
The gate is an engineering screen, not proof that false support is impossible.

Comparisons and utility limits
Before inference, freeze always-insufficient as a weak 1/3 verdict baseline and a
simple lexical excerpt ranker for proof coverage on the 16 decisive cases. The
ranker is not a valid full-task classifier and may return irrelevant citations.
Report saturation honestly; a lookup-friendly pack cannot demonstrate broad
reasoning ability or value beyond document retrieval plus human review. Specialist
search/manual review and configuration validators are unmeasured alternatives.
No cost, productivity or efficiency superiority is inferred from this cohort.

Verification and promotion
Keep full raw streams, request prompts/options/schema, clocks, host checks and
cleanup logs. An independent scorer implements verdict/citation/gate checks and
uses established raw transport/controller helpers; it does not import the primary
scorer. Source offsets/transforms and code/protocol/source freezes are checked.
Independent outcome audit must agree before a pass is reported. Runtime tests
use synthetic fixtures and mock servers; they never count as measured outcomes.
A pass permits a separately designed service trial using fresh cases and a
human-reviewed correctness contract. Arrival/latency/full-horizon energy work
requires its own prospective protocol. Two compatible hardware configurations
and actual independent-owner pooling evidence remain separate open gates.
