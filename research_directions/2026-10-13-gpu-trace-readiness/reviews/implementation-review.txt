Actionable findings
A. Provenance hardening: verify_inputs currently validates revision equality between
   lock and download record and validates byte identities, but does not validate
   that URL, repository, revision and relative path agree. A simultaneous accidental
   edit of both revision labels or both URLs is not rejected. Actual current inputs
   pass an independent exact URL construction check, so this does not invalidate
   current counts. Enforce a 40-hex pinned revision and the raw-host URL derived
   from the declared supported repository and relative path; include mutation tests.
B. Report the 25 repeated-token augmentation rows explicitly. A later converter
   must not silently repair these into canonical permission lists.
C. Wording caution: SOURCE_MATRIX says default policy is declared unrestricted and
   its prohibited-inference wording groups nan and blanks. The README explicitly
   defines literal nan as unrestricted, while downloaded defaults contain blank
   cells. Current analyzer sensibly retains blank separately. Prefer equally clear
   prose in the final report: baseline source description plus blank-cell counts;
   do not claim a blank CSV token itself supplies a measured per-job type policy.
