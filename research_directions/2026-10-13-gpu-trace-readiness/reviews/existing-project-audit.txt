MAC MODEL BOUNDARY
The M3 unified-memory device does not satisfy the present interpretation of
whole independent discrete GPUs each with separate VRAM and shared host RAM.
Its 30 GPU cores cannot become 30 GPU resources; its 96 GB cannot simultaneously
be counted as separate host RAM and device VRAM. Software parallel slots are not
independent GPU ownership units. Existing Mac measurements remain useful local
serving evidence, but provide no real validation of this placement model. The
placement REPORT.txt:73 already records this boundary.

MINIMAL NEXT INTEGRATION BOUNDARY
Obtain an explicitly supplied, read-only snapshot from a known operator/scheduler
covering one or a few discrete-GPU nodes and at most 8 pending jobs. Keep raw
source values, capture UTC, source/version, units and mapping provenance; fail
closed on missing fields instead of assigning default capacity/permissions.
Required resource facts: node identity alias, owner declaration, independently
allocatable CPU and host RAM, actual GPU IDs/type/total usable VRAM and which
whole devices are available according to authoritative reservations. Required
job facts: stable alias, admitted-resource demand (GPU count, per-device minimum
VRAM, CPU, host RAM), allowed families/owners, externally declared priority and
pending state. Arrival timestamps aid provenance but do not alter this snapshot
objective; never infer pending state from a completed-request trace.

CPU units must use an explicit scheduler conversion (e.g. millicores versus
cores), and capacity/demand must share that unit. Family naming must map real
device/compatibility profiles to declared IDs; same name does not itself prove
driver/container/topology compatibility. Sensitive raw identities need not be
published; deterministic local aliases can preserve mapping privately.

An importer should preserve unsupported fields/reasons in a separate audit and
refuse conversion when they affect feasibility. It should not query arbitrary
stored cloud contexts or credentials. A fresh reservation and execution test is
separate from solving a historical snapshot; do not dispatch from stale data.
No additional local benchmark is needed to establish the present missing-data
boundary. A hardware intake/validation tool can be prepared before access exists.
